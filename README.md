# ColonyCount

**Deep-learning detection, counting and species identification of microbial colonies on Petri-dish photos.**

Counting colonies on agar plates is a daily task in microbiology labs, for example in environmental monitoring of pharmaceutical clean rooms and in sterility and water testing. It is usually done by hand, which is slow, tiring and varies from person to person. ColonyCount takes a photo of a plate and:

1. **Classifies the plate** as *empty*, *countable* or *uncountable* (a confluent lawn too dense to count).
2. **Detects every colony** on countable plates with a fine-tuned Faster R-CNN, including at 6000 × 4000 px, by processing the plate in overlapping tiles.
3. **Identifies the species** of each colony (5 microbes), and keeps defects and contamination out of the count.
4. **Reports per-species counts.** These are scored against expert counts with MAE and sMAPE, and the boxes are scored with COCO mAP.

```
plate photo ──► plate classifier (ResNet-18) ──► empty / uncountable → report, stop
                         │ countable
                         ▼
        512-px overlapping tiles ──► Faster R-CNN (COCO-pretrained, fine-tuned)
                         │
        merge duplicates across tiles (intersection-over-smaller-box)
                         ▼
        per-species counts + annotated image + JSON
```

## What's inside

| Component | File | What it does |
|---|---|---|
| Dataset conversion | `scripts/agar_to_coco.py`, `scripts/inspect_agar.py` | AGAR per-image JSON → COCO train/val/test, split by background type (as in the AGAR paper) |
| Patch sampling | `colonycount/data.py` | Cuts 512-px training patches centred on colonies, plus a few % empty agar patches |
| Augmentation | `colonycount/data.py` | Flips, 90° rotations (plates have no "up"), brightness/contrast (AGAR lighting varies a lot) |
| Detector | `colonycount/model.py` | Faster R-CNN ResNet-50-FPN v2 (or MobileNet-v3 for laptops), **anchors shifted one octave smaller** for small colonies |
| Whole-plate inference | `colonycount/infer.py` | Sliding window; duplicates merged by **intersection-over-smaller-box**, with boxes cut by a tile edge ranked last |
| Plate classifier | `colonycount/model.py`, `train_plate.py` | ResNet-18 on the downscaled plate; class-weighted loss for imbalance |
| Metrics | `colonycount/metrics.py` | COCO mAP via pycocotools (detection cap raised from 100 to 1000 per plate), per-class AP, counting MAE / sMAPE |
| Count threshold | `tune.py` | Picks the score threshold that minimises count error on validation plates |
| Tests | `tests/test_core.py` | Tile merging counts every colony once, box-safe augmentation, metrics, patch sampling |

## Dataset: AGAR

[AGAR](https://agar.neurosys.com/) (Annotated Germs for Automated Recognition, NeuroSYS) has about 18,000 plate photos and 336,442 colonies annotated by microbiologists ([paper](https://arxiv.org/abs/2108.01234)).

- **Species:** *S. aureus, B. subtilis, P. aeruginosa, E. coli, C. albicans*, plus annotated defects and contamination.
- **Higher-resolution subset:** 6000 × 4000 px, in *bright*, *dark* and *vague* lighting.
- **Lower-resolution subset:** 2048 × 2048 px.
- **Plate labels:** each plate is countable, uncountable (`colonies_number = -1`) or empty.
- **License:** CC BY-NC 2.0. Free for academic research; the full set needs a sign-up form on the AGAR site. A demo zip is linked directly on the page.

## Quick start

```bash
pip install -r requirements.txt
pytest -q tests

# 1. data: put the AGAR images + json files in raw/agar/
python scripts/inspect_agar.py --src raw/agar          # check the json key names first
python scripts/agar_to_coco.py --src raw/agar --out data/agar
python scripts/make_patches.py --data data/agar --img-root raw/agar

# 2. train
python train.py --data data/agar --img-root raw/agar --epochs 12           # detector
python train_plate.py --data data/agar --img-root raw/agar --epochs 8      # plate classifier

# 3. tune on validation, then evaluate on test
python tune.py --ckpt runs/det/best.pt
python evaluate.py --ckpt runs/det/best.pt --plate runs/plate/best.pt --count-thr <from tune>
python scripts/make_figures.py --ckpt runs/det/best.pt --log runs/det/log.csv --results results --count-thr <from tune>

# 4. use it
python count.py some_plate.jpg --ckpt runs/det/best.pt --plate runs/plate/best.pt --count-thr <from tune>
```

**No data yet?** `python scripts/make_synthetic.py --out raw/synthetic`, then run the same commands with `--src raw/synthetic`, `--img-root raw/synthetic` and `--data data/synth` to check that everything runs.

**About the converter:** the AGAR paper describes each JSON file's fields (background, colony count, and boxes with x, y, width, height and class), but the exact key names in `agar_to_coco.py` are a best guess. Run `inspect_agar.py` first and edit the `KEYS` dict if they differ. If your download already includes COCO files, use those instead.

## Running on a Mac (Apple Silicon)
- **GPU:** every script uses the Apple GPU (MPS) automatically. `PYTORCH_ENABLE_MPS_FALLBACK=1` is set internally, so detection ops without an MPS kernel fall back to the CPU instead of crashing.
- **Workers:** use `--workers 0` on macOS.
- **Model choice:** start with `--arch mobilenet` for a quick first run, then train the ResNet-50 model for the real results.
- **Training time:** not measured yet. Run `--epochs 1 --max-steps 50` first to estimate it.

## Design decisions

**Why detection, not segmentation?** Labs need *counts* and *species*, not colony outlines. AGAR is also annotated with boxes, so an object detector is the natural fit.

**Why smaller anchors?** COCO-pretrained Faster R-CNN starts its anchors at 32 px. Many colonies in a 512-px patch are smaller than that, so every anchor size is shifted down one octave (16–256 px).

**Why intersection-over-smaller-box for merging?** A colony on a tile border is detected twice: once whole, and once cut off by the tile edge.
- **Standard NMS misses this:** it uses IoU, and a half box against a whole box has an IoU of only about 0.5, so both are often kept and the colony is double-counted.
- **Smaller-box overlap catches it:** the cut copy sits inside the whole one, so its intersection-over-smaller-box is about 1.
- **The whole copy wins:** boxes touching an interior tile edge are ranked last, so the complete copy is the one kept.
- **Overlap setting:** the tile overlap (128 px by default) must exceed the largest colony, so every colony appears whole in at least one tile.
- **Tested:** see `tests/test_core.py::test_sliding_window_counts_each_colony_once`.

**Why a separate counting threshold?** mAP averages over every confidence level, but a lab needs one number per plate. The count threshold is therefore tuned for counting error on validation plates, never on test.

**Why a plate classifier first?** An uncountable lawn should be flagged, not given a misleading count. Empty plates skip the detector entirely, which saves time on the most common negative result.

## Possible extensions
- Cascade R-CNN or a DETR-style detector (the AGAR paper's best baseline was Cascade R-CNN)
- Test-time augmentation (flips) on each tile
- A small web UI for lab technicians: upload a plate, review the boxes, export counts
- Domain-shift study: train on *bright* plates, test on *dark* and *vague* ones
